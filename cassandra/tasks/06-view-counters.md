# Задание 06. Счётчики просмотров ★

**Бизнес-контекст:** у поста считают просмотры. Тысяча читателей нажимают «открыть» одновременно.
Прочитать число, прибавить единицу и записать обратно — значит потерять часть просмотров: два
клиента прочитают 10 и оба запишут 11. Колонка типа `counter` умеет прибавлять на сервере.

## Что нужно сделать

- Отдельная таблица `guide.post_views`. Ключ — `post_id`. Единственная колонка `views` имеет тип
  `counter`. Рядом с ней нельзя хранить обычные поля поста: текст, автор, время.
- `addViews` прибавляет `delta` к счётчику. Не читайте текущее значение в Java, чтобы прибавить его сами.
- `views` возвращает накопленное число. Если пост ещё никто не смотрел, верните `0`.

## API

```java
public final class ViewCounters {
    public ViewCounters(CqlSession session);

    void ensureSchema();
    void addViews(String postId, long delta);
    long views(String postId);
}
```

`ensureSchema` вызывают один раз, до остальных методов: он создаёт таблицы и готовит запросы, без него остальные методы упадут с `NullPointerException`.

## Как проверить

```bash
bash scripts/mvn-docker.sh -Ptasks -pl cassandra/tasks test -Dtest='dev.nosqlguide.cassandra.tasks.task06.*Test'
```

Эталон:

```bash
bash scripts/mvn-docker.sh -pl cassandra/solutions test -Dtest='dev.nosqlguide.cassandra.tasks.task06.*Test'
```

Почему через `scripts/mvn-docker.sh`, а не напрямую `./mvnw` — [cassandra/README.md, раздел «Как запускать тесты»](../README.md#как-запускать-тесты).

- `missingPostHasZeroViews` — неизвестный пост читается как ноль.
- `incrementsAddUp` — прибавления 1, 1 и 3 дают 5.
- `anotherPostStaysAtZero` — чужой пост не меняется.

## Подсказки

<details>
<summary>1. Счётчик живёт отдельно от поста</summary>

Таблица счётчиков не хранит текст поста. Это ограничение типа `counter`, а не вкусовщина:
обычную колонку и счётчик в одной таблице объявить нельзя. Ограничения счётчиков собраны в разделе
[«Счётчики»](../theory/08-lwt-batches-counters.md#счётчики).
</details>

<details>
<summary>2. Прибавление — одна команда</summary>

Серверу говорят «прибавь N», а не «запиши вот это число». Первое обращение создаёт счётчик само,
отдельная вставка нуля не нужна.
</details>

## Подумайте после решения

- Два клиента прочитали 10 и оба записали 11. Сколько просмотров потерялось и почему счётчик
  этого не делает?
- Почему по счётчику нельзя понять, кто именно посмотрел пост?
- Первый `UPDATE` применился, но ответ потерялся по дороге, и клиент повторил запрос. Что стало
  с числом? Почему повторять прибавление счётчика вслепую нельзя, а повторить `INSERT` той же строки — можно?
