# 00. Общая теория NoSQL

Этот раздел — фундамент для всего репозитория. Здесь нет привязки к одной СУБД: разбираются идеи, на которых построены Redis, MongoDB и Cassandra, — модели данных, согласованность, репликация, партиционирование, консенсус, устройство хранения и моделирование. Без этих понятий теория по конкретным СУБД читается как набор «магических» настроек.

## Оглавление

| # | Файл | О чём |
|---|---|---|
| 01 | [Зачем появился NoSQL](01-why-nosql.md) | Пределы реляционной модели при масштабировании, история (Bigtable, Dynamo), когда NoSQL не нужен |
| 02 | [Классификация NoSQL-хранилищ](02-classification.md) | KV, документные, wide-column, графовые, векторные, time-series, поисковые; ClickHouse как смежная OLAP |
| 03 | [CAP, PACELC и модели согласованности](03-cap-consistency.md) | Что на самом деле утверждает CAP, PACELC, от linearizable до eventual и read-your-writes |
| 04 | [Репликация](04-replication.md) | Leader-follower, multi-leader, leaderless и кворумы `R + W > N` |

## Рекомендуемый порядок чтения

1. **01 → 02** — зачем всё это и какие бывают NoSQL-системы.
2. **03 → 04 → 05 → 06** — распределённые системы: согласованность, репликация, партиционирование, консенсус. Файлы опираются друг на друга, лучше читать подряд.
3. **07** — что происходит внутри одной ноды при записи и чтении.
4. **08** — как проектировать схему; этот файл использует понятия из всех предыдущих.

После раздела переходите к теории конкретной СУБД (Redis, MongoDB или Cassandra) — порядок между ними не важен. Если времени мало, минимальный набор перед практикой: 01, 03, 04, 08.

## Как читать

- Каждый файл начинается с блока **«Коротко»** — суть на 3–5 предложений. Если нужен только итог, прочитайте его и раздел «Итоги» в конце.
- Разделы с пометкой **🔬 Глубже** содержат внутренние алгоритмы, формулы и граничные случаи. При первом чтении их можно пропустить — остальной текст понятен и без них.
- Каждый термин объясняется при первом упоминании: жирным шрифтом, с английским вариантом в скобках.
- В конце каждого файла — вопросы для самопроверки с ответами под спойлером. Попробуйте ответить сами, прежде чем раскрывать.
- Раздел «Как это выглядит в Redis / MongoDB / Cassandra» в каждом файле связывает общую идею с тремя СУБД, которые изучаются в репозитории.
